Client Website IA & Page Section Roadmap

Goal: restructure the public/client-facing website into a clear wedding platform journey: inspire, choose invitations/products, find providers, plan the event, and convert to inquiry/checkout/account.

Research references checked:
- Zola: wedding websites, vendors, invites, guest list, budget, seating chart, registry, expert help.
- The Knot: invitations + wedding website, RSVP tracking, registry, vendor discovery, planning tools.
- WeddingWire: vendor directory, checklist, budget, guest list, seating chart, cost guide, inspiration.
- Minted Weddings: premium stationery, free wedding websites, timeline by wedding stage, sample kits, invitation finder, expert consultation.

Core Project Snapshot:
- Public pages mostly use managed pages rendered by `managed-page-renderer`.
- Existing capabilities: offerings, digital templates, paper products, builder templates, public invitation sites, wishlist, checkout/orders, provider/service flow foundations, ads/provider priority, blog/content, tools, managed pages, media library, menus, SEO.
- Current Home already has hero, ad banner, about, services, event planner, invitation gallery, shared invitations, and FAQ, but the journey/order needs to be clearer.

Top-Level Principles:
- [ ] Public website must speak in customer language, not admin/internal architecture.
- [ ] Route language rule: public client-facing routes use Vietnamese slugs; admin/provider/customer protected routes and internal API routes use English slugs only.
- [ ] First viewport must immediately explain PinkLove: wedding invitation/website + paper products + provider services + planning tools.
- [ ] All public pages should share one visual system.
- [ ] Use real template/product/provider media from DB whenever possible.
- [ ] Repeated content can use cards; avoid decorative card-in-card wrappers.
- [ ] Every major section must have a concrete CTA.
- [ ] Sponsored/provider priority placements must be visibly labeled.
