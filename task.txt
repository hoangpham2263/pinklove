Task: Flexible Ads / Announcement Display System

Goal:
- Build an admin-controlled public display system for ads, hot news, promotions, and announcements.
- Admin can choose where items appear, how many appear, when they are active, and whether each placement/campaign is enabled.
- Admin can choose exact public pages/routes where a popup should appear; if the current page does not match the configured target pages, the popup must not render.
- When a visitor closes a popup/floating ad, the site remembers that dismissal for the configured time so it does not keep bothering the user.

Implementation Principle:
- Extend the existing Ads module. Do not create a separate `announcements` or `popups` domain unless the current ads model cannot support it.
- Treat this as an isolated Marketing Ads feature. It must not change checkout, offering, booking, provider, auth, customer, or admin workflows.
- Popup, floating, and global bar rendering must use one centralized host imported once in the public guest layout, not ad-hoc imports in individual pages.
- Public pages must keep working normally when there is no ad config, invalid ad metadata, no matching target page, or an ads API/server error.
- Overlay ads must be fail-closed: when uncertain, render nothing instead of interrupting the page.
- Use `ad_placements.metadata`, `ad_creatives.metadata`, and `ad_campaigns.metadata` for UI/display rules that are not heavily queried.
- Add relational columns only for fields that must be filtered/sorted often.
- Keep provider priority separate from generic site ads.
- Keep all anonymous dismissal state client-side. Do not write popup dismissal into users, orders, bookings, providers, or customer profiles.

Feature Scope:
- Banner ads in fixed page sections.
- Floating ad widgets.
- Modal popup announcements.
- Top/bottom announcement bars.
- Configurable page targeting and suppression after close.
- Page-specific popup targeting: show only on selected pages, route patterns, or page groups.

Recommended Data Model:
- Reuse `ad_placements` for render slots.
- Extend placement behavior through metadata:
  - `displayMode`: `inline_banner`, `modal`, `floating`, `top_bar`, `bottom_bar`
  - `position`: `top`, `bottom`, `left`, `right`, `center`, `bottom_right`, `bottom_left`
  - `maxItems`: already exists as relational `max_items`
  - `rotation`: `priority` or `latest`
  - `globalEnabled`: allowed only for non-intrusive modes such as top/bottom bars and footer/inline banners
  - `showDelayMs`
  - `dismissMode`: `session`, `hours`, `days`, `forever`
  - `dismissTtlHours`
  - `frequency`: `once_until_dismissed` for MVP
  - `pageRules`: include/exclude route patterns; intrusive overlays must show only when current pathname matches an include rule and does not match any exclude rule
  - `targetPages`: selected managed pages/public routes from Admin UI
  - `defaultPageBehavior`: `none` for intrusive modes, so popup/floating never appear globally
  - `deviceRules`: `all`, `desktop`, `mobile`
- Extend campaign behavior through metadata:
  - `priority`
  - `isDismissible`
  - `showCloseButton`
  - `theme`
  - `isSponsored`
- Extend creative behavior through metadata:
  - `layout`: `image_only`, `image_text`, `text_card`, `html`
  - `badgeLabel`

Dismissal / Cookie Tasks:
- [ ] Use cookie for dismissal state so it survives page reloads and server/client boundaries if needed.
- [ ] Also keep an in-memory/sessionStorage guard to avoid duplicate popup during the same SPA session.
- [ ] Cookie key format:
  - `pinklove_ad_dismissed_{campaignId}`
  - optional placement-level key: `pinklove_ad_dismissed_placement_{placementKey}`
- [ ] Cookie value:
  - JSON or compact string containing `dismissedAt`, `campaignId`, `placementKey`, and `mode`.
- [ ] Respect TTL:
  - `session`: no persistent cookie, use `sessionStorage`
  - `hours/days`: cookie with `max-age`
  - `forever`: cookie with long max-age, for example 180 days
- [ ] When visitor clicks CTA, optionally suppress again using `until_clicked` behavior.
- [ ] Do not store sensitive personal data in dismissal cookies.
- [ ] Dismissal keys must be scoped to ads, for example `pinklove_ad_*`.
