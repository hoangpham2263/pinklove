## 3. Data model dich

### Bang `users`

Chuyen thanh:

```sql
users (
  id TEXT PRIMARY KEY,
  email TEXT NOT NULL,
  account_name TEXT NOT NULL,
  password_hash TEXT,
  email_verified_at TIMESTAMPTZ,
  role TEXT NOT NULL,
  account_status TEXT NOT NULL,
  account_status_reason TEXT,
  account_status_updated_at TIMESTAMPTZ,
  account_status_updated_by TEXT,
  created_at TIMESTAMPTZ NOT NULL,
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
)
```

Rang buoc bat buoc:

```sql
CREATE UNIQUE INDEX users_email_normalized_uidx
ON users (LOWER(BTRIM(email)));
```

Quy uoc:

- Email duoc `trim().toLowerCase()` truoc moi query va write.
- Khong cho phep email rong.
- Khong dung `contact_email` de xac thuc.
- `account_name` khong can unique.
- `account_name` khong duoc rong sau khi trim.
- `password_hash` co the nullable chi voi tai khoan OAuth-only.
- Khong hien thi email cong khai neu UI chi can ten.

### Bang `user_profiles`

- Giu `full_name` cho ho va ten phap ly/ho so.
- `account_name` trong `users` la ten hien thi mac dinh.
- Ra soat `display_name`:
  - Trong migration dau tien, van giu cot de tuong thich.
  - Backfill `account_name` tu `display_name`, sau do `full_name`, sau do `username`.
  - Sau khi tat ca code dung `account_name`, danh dau `display_name` deprecated.
  - Chi xoa `display_name` trong migration rieng sau khi audit khong con tham chieu.
- `contact_email` chi duoc giu neu nghiep vu can mot email lien he khac email dang nhap.
- Neu khong co use case email lien he rieng, dong bo ve `users.email`, sau do deprecated `contact_email`.

### Token email

Them bang token dung chung:

```sql
user_email_tokens (
  id TEXT PRIMARY KEY,
  user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  purpose TEXT NOT NULL CHECK (purpose IN ('verify_email', 'reset_password', 'change_email')),
  token_hash TEXT NOT NULL UNIQUE,
  pending_email TEXT,
  expires_at TIMESTAMPTZ NOT NULL,
  used_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
)
```

- Chi luu hash cua token, khong luu raw token.
- Token verify/change email het han sau 24 gio.
- Token reset password het han sau 30 phut.
- Moi purpose chi co mot token active moi nhat cho moi user.

## 4. Chien luoc migration du lieu cu

### Pha A: Mo rong schema

3. Chua dat `NOT NULL` va unique email cho den khi backfill xong.

### Pha B: Backfill account name

```text

-> user_profiles.full_name

```

- Trim ket qua.
- Khong ep account name unique.
- Khong tu dong bien account name thanh slug.
- Provider portal slug tiep tuc dung `provider_portal_slug`, khong dung email.

### Pha C: Backfill email

Thu tu uu tien:

```text
user_profiles.contact_email hop le
-> user_oauth_accounts.email hop le
-> can xu ly legacy
```

Quy tac:

- Tat ca email so sanh bang lowercase + trim.
- Tao bao cao truoc migration:
  - user khong co email
  - email khong hop le
  - email trung nhau
  - mot user co nhieu email khac nhau giua profile va OAuth
- Khong am tham chon mot email trung cho hai user.
- Uu tien account co Google OAuth da lien ket khi email trung voi account local.
- Cac conflict con lai phai duoc ghi log va dua vao danh sach can admin xu ly.
- Khong dung email gia `@pinklove.local` lam email dang nhap cho user that.
- Seed/demo account phai duoc cap email ro rang trong seed data, vi du:
  - `seed-admin@example.local`
  - `seed-customer@example.local`
  - `seed-provider@example.local`

### Pha D: Chuyen code va rang buoc

Sau khi preflight bao cao khong con conflict:

1. Dat `users.email NOT NULL`.
2. Tao unique index tren `LOWER(BTRIM(email))`.
3. Dat `users.account_name NOT NULL`.
4. Chuyen toan bo auth sang email.
5. Doi `username` thanh `account_name` trong database chi sau khi code da san sang.
6. Khong giu che do login username lau dai.
7. Co the giu alias doc tam thoi trong TypeScript trong mot release, nhung khong hien thi va khong nhan username tai API.

### Pha E: Cleanup

- Xoa unique constraint cu cua username.
- Rename/drop cot `username` sau khi audit khong con SQL tham chieu.
- Xoa fallback email `${username}@pinklove.local`.
- Xoa error code `username_taken`.
- Xoa copy "Ten dang nhap", "Username" khoi cac auth screen.
- Danh gia va xoa `user_profiles.display_name` / `contact_email` neu khong con use case rieng.

## 13. Email verification va password reset

### Verify email

- Route gui lai verification email co rate limit.
- Route consume token mot lan.
- Sau khi verify, set `users.email_verified_at`.
- Khong dua raw token vao log.

### Forgot password

- Form nhap email.
- Response luon giong nhau du email co ton tai hay khong.
- Neu account ton tai, tao reset token va gui email.
- Rate limit theo IP va normalized email.

### Reset password

- Validate token hash, expiry va `used_at`.
- Validate password policy.
- Update password hash trong transaction.
- Mark token used.
- Xoa tat ca session cu cua user.
- Tao session moi hoac redirect login theo policy.

## 15. Transaction va concurrency

- Register user + profile phai dung mot database transaction.
- Google create/link user phai dung transaction.
- Unique normalized email index la lop bao ve cuoi cung.
- Duplicate email phai bat theo constraint name, khong bat moi loi `duplicate key value`.
- Doi email phai dung transaction.
- Token consume phai atomic:

```sql
UPDATE user_email_tokens
SET used_at = NOW()
WHERE token_hash = $1
  AND used_at IS NULL
  AND expires_at > NOW()
RETURNING user_id;
```
